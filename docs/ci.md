## Pipeline map

```mermaid
flowchart TB
  triggers["<b>Triggers</b> · ci.yml L4–11<br/>pull_request · push to main · workflow_call (release) · workflow_dispatch (pipeline-opened PRs)"]

  subgraph stageCode["Code"]
    lint["<b>lint</b><br/>style, lint, types<br/>L28–44"]
    secrets["<b>secrets</b><br/>gitleaks, history<br/>L46–63"]

  end

  subgraph stageBuild["Build"]
    build["<b>build</b><br/>compile, ABI, docs<br/>L67–91"]
  end

  subgraph stageTest["Test"]
    test["<b>test</b><br/>contract tests<br/>L95–109"]
    coverage["<b>coverage</b><br/>100% line + branch<br/>L111–126"]
    gas["<b>gas</b><br/>snapshot check<br/>L128–147"]
    slither["<b>static-analysis</b><br/>Slither + SARIF<br/>L149–170"]
    upgrade["<b>upgrade-safety</b><br/>vs latest release<br/>L172–194"]
    web["<b>web</b><br/>tests, then build<br/>L196–216"]
    test ~~~ gas ~~~ upgrade
    coverage ~~~ slither ~~~ web
  end

  gate["<b>CI</b> · the aggregate job · ci.yml L219–231<br/>needs all nine · runs even when one fails · exits 1 unless every result is success"]
  ruleset["<b>Ruleset on main</b> · a GitHub setting, not a file<br/>pull requests only · required status check: CI · no bypass actors"]

  triggers --> stageCode
  triggers --> stageBuild
  triggers --> stageTest
  stageCode --> gate
  stageBuild --> gate
  stageTest --> gate
  gate --> ruleset

  style ruleset stroke-dasharray: 4 4
```

All nine jobs start together, with no ordering between them; the `CI` job is the only one that waits. Line numbers in the boxes are in `ci.yml`.

## Item by item

Each row is one thing CI does: the workflow step that runs it, then the script or config that step leads to.
